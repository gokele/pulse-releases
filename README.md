# Pulse

极简 VPS 探针面板。只做三件事：**在线状态**、**Ping 延迟图表**、**负载图表**。

一个二进制文件加一个 SQLite 数据库就能跑。不需要 Docker，不需要写配置文件，所有设置都在后台点几下完成。

---

## 为什么是它

市面上的探针面板功能越堆越多，装完先要填一堆配置、起一堆容器。如果你只是想知道「我那几十台机器还活着吗、延迟怎么样、负载高不高」，那些东西都是负担。

Pulse 把范围收得很窄，然后把这几件事做扎实。

---

## 面板能看到什么

**节点卡片** —— 在线状态、地区旗标、CPU / 内存 / 磁盘占用、实时网速、累计流量、系统负载，离线节点整张卡片会变色，在一片卡片里一眼就能挑出来。

**Ping 延迟** —— 电信 / 联通 / 移动三网曲线，自动按三网顺序排列。可以单独隐藏某条线，也能看丢包率。

**负载历史** —— CPU、内存、磁盘、网络、连接数、负载的时序图，支持缩放和时间范围切换。

**资产概览** —— 每台机器的价格、计费周期、到期时间。多币种会按**每日自动更新的实时汇率**折算成人民币汇总，快到期的会标红提醒。

**外观** —— 跟随系统的亮/暗主题，手机上也能正常看。

面板可以设访问密码，不设就是公开的。标记为「隐藏」的节点不会出现在公开面板上。

---

## 后台能配什么

不需要改任何文件，全部在 `/admin` 里：

| | |
|---|---|
| **节点** | 新增 / 编辑 / 删除，名称、地区、分组、标签、备注、价格、币种、计费周期、到期时间、自动续费、隐藏 |
| **Ping 任务** | ICMP / TCP / HTTP 三种类型，自定义目标、间隔、超时、执行范围 |
| **站点设置** | 站点名、描述、默认外观、访问密码、上报节奏、历史保留天数、汇率 |
| **安全** | 修改用户名密码、绑定 GitHub 账号登录 |
| **备份** | 导出/导入配置，或下载完整数据库 |

几个值得一提的细节：

- **每台机器一把独立密钥**，不是全局 token。新建节点时自动生成，后台直接给出带密钥的一键安装命令。
- **GitHub 登录需要先绑定**。配好 OAuth 之后点「绑定我的 GitHub 账号」走一次授权，只有绑定过的账号能登录后台——不会出现「有 GitHub 账号就能进」。
- **从 Komari 导入**。填上原面板地址就能把节点和 Ping 任务批量搬过来，机器多的时候省事。
- **汇率每天只同步一次**，存在数据库里，也可以手动改；手动改过的币种不参与自动同步。

## Agent

- 支持 **Linux amd64 / arm64 / armv7**
- 二进制约 7 MB，运行时内存占用二十几 MB
- systemd 托管，**以非 root 的专用账号运行**，只保留 ICMP 需要的那一项权限
- 采集全部走 `/proc`，不执行任何外部命令
- **自动更新**（可选，默认关闭）：发现版本与面板不一致时自行下载新版本，**校验 SHA-256、试运行确认版本无误后**才替换自己并重启；任何一步不通过就保留原版本继续跑

## 更新

面板每天自动检查一次新版本。「站点设置 → 关于」里可以看到当前版本与最新版本。

点「更新服务端」会先弹出这个版本的更新内容，确认后自动完成：下载 → 校验 SHA-256 → 试运行确认版本 → 替换 → 重启。

几条保证：

- 校验不过、或新二进制跑不起来，一律放弃更新，原版本继续跑
- 替换前旧二进制会备份为 `pulse-server.prev`，万一新版本起不来，一条命令即可回滚
- 不是由 systemd 托管的进程会拒绝就地更新（退出后没人拉起，等于把面板弄没了）
- 更新期间面板有几秒不可用，Agent 的上报会自动重试，不丢数据

## 安装

### 服务端

从 [Releases](../../releases) 下载对应架构的包：

```bash
tar -xzf pulse-<版本>-linux-amd64.tar.gz
cd pulse-<版本>-linux-amd64
sudo ./install-server.sh
```

脚本会装好 systemd 服务并启动。首次启动的管理员密码打印在日志里：

```bash
journalctl -u pulse-server -n 30
```

默认监听 `8899`，面板在 `http://<你的IP>:8899`，后台在 `/admin`。

想换端口，装的时候带上即可：

```bash
sudo ./install-server.sh --port 9000
```

装好之后改端口：编辑 `/etc/pulse/server.env` 里的 `PULSE_LISTEN`，然后 `systemctl restart pulse-server`。

生产环境建议前面放个 Nginx/Caddy 做 HTTPS。

### Agent

在后台新建节点，点「安装命令」，把给出的命令粘到目标机器上执行：

```bash
curl -fsSL https://你的面板地址/install.sh | sudo bash -s -- --id hk-1 --token <该节点的密钥>
```

卸载：

```bash
curl -fsSL https://你的面板地址/install.sh | sudo bash -s -- --uninstall
```

## 默认行为

| 项目 | 默认值 |
|---|---|
| 上报间隔 | 3 秒 |
| 离线判定 | 30 秒没有上报 |
| 负载历史保留 | 7 天 |
| Ping 历史保留 | 14 天 |
| 监听端口 | 8899 |
| 数据目录 | `/var/lib/pulse` |

超过「原始精度」时长的历史会自动压缩（负载压成 10 分钟一个点，Ping 压成 5 分钟一个点），数据库不会无限增长。以上全部可以在后台改。

## 常见问题

**忘记后台密码了**

```bash
systemctl stop pulse-server
sudo -u pulse /opt/pulse/pulse-server reset-password -data /var/lib/pulse
systemctl start pulse-server
```

会打印一条新的随机密码，同时让所有已登录设备退出。

**面板放在 CDN 后面，Agent 上报失败**

多半是 CDN 的 Bot / WAF 规则把上报请求拦了。两种解法：

1. 在 CDN 上给 `/api/agent/` 加放行规则，关掉该路径的 Bot 与托管规则；
2. 或者给上报单独开一个不过 CDN 的域名（DNS 直连），Agent 的 `--server` 指向它，面板 UI 继续走 CDN。

真被拦时 Agent 日志会直接写明是谁拦的、该放行哪个路径，不用猜。

**数据存在哪，怎么迁移**

全部在 `/var/lib/pulse`。迁移有两种方式：

- 后台「导出配置」拿到一个 JSON，在新机器上导入即可。**节点密钥会一起迁移**，原有 Agent 只要把 `--server` 指向新地址就能继续上报。
- 或者直接下载完整数据库（含历史记录）搬过去。

> 配置备份里包含节点密钥与访问密码，请妥善保管。

**同一个数据目录里的 `secret.key` 是什么**

数据库里节点密钥、访问密码这类机密字段的加密密钥。**备份数据库时要连同它一起保存**，但建议和备份分开存放。丢了它，那些字段就解不开了。

**支持 Windows / macOS 节点吗**

Agent 目前只发布 Linux 版本。

## 系统要求

- **服务端**：任意 Linux，x86_64 或 arm64，二十几 MB 内存足够
- **Agent**：Linux，x86_64 / arm64 / armv7，二十几 MB 内存
- 都不依赖外部数据库、运行时或容器

## 下载

所有版本在 [Releases](../../releases)。每个版本包含：

- `pulse-<版本>-linux-<arch>.tar.gz` —— 完整安装包（服务端 + Agent + 安装脚本）
- `pulse-agent-linux-<arch>` —— 单独的 Agent 二进制
- `checksums.txt` —— 上述所有文件的 SHA-256

下载后建议核对一下：

```bash
sha256sum -c checksums.txt --ignore-missing
```
